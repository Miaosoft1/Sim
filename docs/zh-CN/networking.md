# 网络原型

[项目概览](../../README.zh-CN.md) · [English](../en/networking.md)

## 组合

`Protocol` 提供版本化契约及按方向显式注册的 YAML 消息编解码；SignalR 负责连接和
RPC 封装，事件载荷仍为 YAML，不声称把 SignalR 自身封装替换成 YAML。
`Runtime.Abstractions` 定义模拟与观察接缝；`Runtime` 结合 `Context.NextAsync`
串行处理入站；`Server` 适配真实 Combat 事件及观察；`Server.Hosting` 绑定 SignalR，
不引入账号、匹配或计分实现。Client／Console 不引用服务端实现。
中性竞技场及数值归服务端应用，其规范 YAML 与 LocalCombat 共享。

## 接入与观察

匿名演示接入须显式启用，示例服务端只监听一个回环地址。宿主选择预配置的两名参与者，
签发随机、内存态、绑定会话的凭据；名称不能认领其他角色。
重连使旧连接代次失效，先准备完整快照，客户端应用后确认，再接收缓冲更新。
凭据不持久化，record 文本输出会脱敏。

世界及模块更新以同一状态版本原子发布。模块能力显式声明 ID 和版本；
完整快照为所有协商模块给出完整状态或明确移除，后续帧缺席仅表示无变化。
增量须有已建立状态。共同宿主在调用自定义投影器前，强制向无控制角色的接收者
发送角色私有模块移除。未知版本及重连时丢弃已建立模块均被拒绝。
客户端模块编解码须返回分离的不可变状态。准备期间缓冲有界，溢出使旧快照失效并
要求重新准备，不静默丢更新；新的完整准备保留旧准备及缓冲帧中的未交付业务结果，
但不据此声称已经发送过的结果具备持久化保证。
完整／增量解码方法接收当前 `SessionBinding`，私有模块应在整帧提交前校验所属角色。

世界观察包含地图实例身份及房间／走廊几何、仅自己的经验、实际可见的在途投射物，
以及带 Status 展示标签的已应用能力。状态保留原运行／应用身份和来源；
模拟到期时间查询当前已提交的安装租约，不拿配置时长当剩余时间，
也不假定应用 ID 等于租约 ID；真实时间租约单独报告剩余墙钟时间。
重连恢复已有投射物，命令激活完成不等于稍后已经命中。

`ProjectileFact` 发布已确认的发射、语义命中及爆炸，保留真实投射物／能力／地图身份、
执行时间和命中位置。发射在弹道设置成功后发布；分别投递给接收器的命中不是新命中。
它们是服务端单向瞬时消息，按当前观察者的实际位置可见性投影，仅发给已确认的在线连接，
不在快照准备、溢出、断线或重连期间保留。完整快照只恢复在途状态，不重播施法音效或历史命中；
业务结果仍按独立规则保留。表现层对同一投射物同一位置的爆炸优先播放爆炸而非命中特效；
消息不重复结算战斗，也不强制资源系统。

六边形地图还发布真实可用轴坐标、权威世界中心、格子尺寸、原点和朝向，不公开占用及预留字典。
入口根据实际地图连接及当前受控单位的可见性投影；无受控单位时不发布入口。
目标实例 ID 只表示连接，不等于允许进入，更不授权观察目标世界；角色的返回路径不公开。
SDK 在整帧提交前验证并冻结嵌套几何，非法几何不能部分覆盖原世界。
两种朝向、真实棋盘移动、入口可见性及完整恢复均由
[现有网络示例](../../samples/NetworkSession/NetworkSessionSample.Maps.cs)验证。

## 入队确认不是业务结果

每名参与者从操作号一开始。先验证当前连接及输入权限，再查询最近 **1024** 条已受理确认。
完全相同的重试返回原确认，不重复入队；同号不同内容冲突，窗口外旧号明确过期，
跳号返回期望号；无效输入及队列满不推进操作号。
`long.MaxValue` 保留给耗尽状态，不可受理。无权限时不返回下一操作号提示。

操作号、关联 ID、发布号各自独立；多个操作可共享关联 ID。
重连返回下一受理号，不表示快照已体现此前全部操作。
业务结果是另行发布的类型化服务端事件：施法成功表示命令执行，不保证稍后命中；
移动成功表示目的地已更新，不表示已经抵达。
SDK 保留未解决操作的原内容及原操作号；传输失败后不静默换号、重建或补放。
过期／未知结果不得换新号盲目再执行。

`OperationResult.Status` 明确区分 `Succeeded`、`Rejected`、`Aborted`、`Unknown`；
`Unspecified` 非法，`Reason` 说明具体原因。`Aborted` 表示已受理但被阻止执行；
`Unknown` 不承诺没有副作用，更不表示可以换新号重放。

## 完成态

只有可信宿主可以请求结束，客户端 Hub 不提供该操作。结束先等待当前时间戳的事件／
处理器链结算，再记录终结事件、丢弃未执行战斗并冻结模拟时间。
已进入执行但尚无终局结果的操作返回 `Unknown`；尚未执行的排队输入返回 `Aborted`。
重连快照仍保持完成态，客户端拒绝将其恢复为运行态的后续帧。
模式结果事件实现 `ISessionResultRecordEvent.CreateResultRecord()`，宿主在
`Execute` 赋值后调用；不使用可能在入队日志打印时被提前求值的 record 计算属性。

同一串行执行者继续处理显式允许的完成态输入及实时租约清理，不恢复旧战斗队列。

## 可选 Loadout 适配

`Miaosoft.Sim.Loadout.Protocol`、`.Server`、`.Client` 单独选择，基础 Combat Server、
Client 和 Console 不引用它们。两端使用 `EventCodec.CreateBuilder().AddLoadout()`；
以真实单位功能及可信交换／死亡目录组合 `LoadoutSessionSimulation`，
将其 `Observation` 注册到宿主。适配器依赖 `Runtime.Abstractions`，不依赖执行循环实现
或具体战斗宿主。SDK 选择 `LoadoutClientModule` 协商第一版 `loadout` 观察模块。

成员会变化时，传入 `Func<LoadoutSessionFeatures>`，而不是固定集合。
玩法在启动阶段或已有串行事件链内发布新的、绑定 Context 的成员快照；
该提供器不是跨线程修改入口。成员集合复制并冻结，但单位、库存、交换仍指向原运行时对象，
不是世界状态的深拷贝。权限评估、实际执行和观察均读取当前成员；
功能移除后，尚未执行的输入明确拒绝，已经执行的操作仍保留原提交接收器以发布真实结果。
移除目录成员前，应先通过领域事件关闭交换、清理死亡授权，不能以隐藏目录代替领域清理。

库存所有者不等于可登录参与者：可以加入 NPC 库存及死亡目录，但不会增加接入凭据或控制绑定。
只有 `ISessionSimulation.ParticipantUnitIds` 中的单位可以提交参与者命令。
快照构造校验原库存归属和同一 Context，提供器返回其他 Context 的快照会明确失败；
死亡处理器注销后，私有观察与后续命令同步失效。
模式状态和启动完成前的发布屏障仍由玩法宿主负责。

世界单位会变化时，`BattleSessionSimulation` 可另传 `worldUnits` 提供器。
构造时的单位列表仍是固定接入名单；提供器维护用于可见性、目标查找及投射物观察的已初始化原单位。
后加入的 NPC 可以被观察和选为目标，但不会因此成为可登录角色。
目录只在启动阶段或同一执行链内修改；其他 Context 的单位、冒用角色 ID 的替换对象会明确失败，
排队命令在实际执行前再次校验。移除世界条目不等于销毁领域状态或撤销已有授权。

网络请求只携带 ID 及预期版本，不传运行时库存对象：

- 装备／卸下／丢弃绑定当前持有者的精确原物品及库存版本；
  创建和获取物品仍是可信玩法操作，不开放给客户端。
- 天赋分配绑定角色自己的树、修订及授权代次；客户端不能自行发点或授权树。
- 交换绑定当前登记的双方库存、精确实例、目标槽位及版本化双边同意；
  只展示对方已提出交换的物品，不暴露其余库存。
- 死亡检查／领取绑定已有授权及原领取者；Loadout 中只有这两种命令在完成后仍可使用。
  范围、遗体、库存版本或授权失效时移除检查详情，领取仍通过原领域事务重新验证。

第一版观察在状态改变时发送完整、不可变替换，失去控制时明确移除，不另造增量协议。
库存、角色树点数／等级／进度、交换条款／同意和已检查的死亡物品与世界同帧提交。
转移保留原物品及原能力身份；角色树与点数不随物品移动。
实现及真实网络用例见 [NetworkSession](../../samples/NetworkSession/NetworkSessionSample.Loadout.cs)；
基础交互式 Console 有意仅保留 Combat 功能。

## 当前限制

这不是生产身份体系、持久化恰好一次语义、跨进程恢复或分布式协调。
输出队列有界，超载明确失败。目前已接入基础 Combat 命令及上述世界观察；
私人兼容仍待迁移。
NetworkSession 测试覆盖真实回环战斗／状态／在途重连、已受理未执行快照、
准备缓冲溢出、精确确认窗口、混合队列压力、
权限、模块完整／增量／移除、完成态、结果记录、可选 Loadout 及显式演示启用，
不代表整体迁移或生产验收完成。
